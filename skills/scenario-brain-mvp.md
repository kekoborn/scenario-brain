# Scenario Brain MVP — Сценарный скилл для видео Михаила Дашкиева

## Назначение

Система для создания сценариев видео в стиле Михаила Дашкиева через управляемый процесс:
- **Discovery-бриф** → Сверка с TOV → **Research** → Выбор структуры → Сценарий по блокам → Редактура → Финал → **Визуальный слой** → **Хуки**

**Главный принцип:** Не писать полный сценарий сразу, а вести команду по этапам.

**Версия:** 1.7 (+ Discovery-interview + Hooks)

---

## Этапы работы MVP

### Этап 0: Discovery-interview бриф (НОВЫЙ)

**Задача:** Быстро и точно понять, что за видео делаем — через живой диалог, а не анкету.

**Принцип:** Следующий вопрос зависит от предыдущего ответа. Как в интервью.

**Процесс:**

1. **Определяю тип видео** (первый вопрос):
   - Обучающее (методология, протокол)
   - Продающее (вебинар, продукт)
   - Кейс (история компании)
   - Мотивационное (mindset)

2. **Выбираю ветку вопросов** в зависимости от ответа:
   
   **Если "Обучающее":**
   - Это протокол (делай 1→2→3) или концепция (поймёшь → изменится мышление)?
   - Зритель уже в ситуации или готовится?
   - Сколько шагов в протоколе?
   - Есть готовые кейсы для доказательства?
   - Что зритель сделает СРАЗУ после просмотра?
   
   **Если "Продающее":**
   - Что продаём? (продукт/услугу/событие)
   - Это решение боли или возможность роста?
   - Главный барьер покупки? (цена/время/скепсис)
   - Что после просмотра? (купить/лид-магнит/звонок)
   
   **Если "Кейс":**
   - Успех, провал или трансформация?
   - Главный контраст до/после?
   - Зритель может повторить или вдохновляется?
   
   **Если "Мотивационное":**
   - Про mindset или про действие?
   - Что должно произойти в голове зрителя?

3. **Задаю общие вопросы** (для всех веток):
   - Целевая длина видео?
   - Откуда берём контент? (транскрипт/звонок/с нуля)
   - Ключевая фраза, которую зритель должен запомнить?

4. **Собираю итоговый бриф** из ответов

**Выход:**
```markdown
# Итоговый бриф (из discovery-interview)

**Тип:** Обучающее (протокол)
**Тема:** Антикризисный протокол
**Аудитория:** Собственники в кризисе
**Формат:** 4 шага, 40-45 мин
**Ключевая фраза:** "Кризис — это не паника. Это протокол."
**Доказательства:** М.Видео, Airbnb, кризис 2008
**Действие:** Скачать таблицу, заполнить, созвать совещание
**Источник:** Есть транскрипт
```

**Время:** 5-7 минут (вместо 30 минут статичной анкеты)

**Детали:** См. `templates/discovery-brief.md`

### Этап 1: Брифование (классический — если не использовали Этап 0)

**Задача:** Понять, что за видео создаётся.

**Процесс:**
1. Если пользователь уже дал часть информации — восстанавливаю бриф сам
2. Показываю, что понял:
   ```
   Я предварительно понял задачу так:
   Тема: ...
   Цель: ...
   Аудитория: ...
   
   Что нужно уточнить:
   1. ...
   2. ...
   ```
3. Задаю недостающие вопросы из шаблона брифа

**Быстрый бриф (для коротких видео):**
- Тема
- Цель  
- Зритель
- Главная мысль
- Что зритель должен сделать после просмотра

**Глубокий бриф (для методологических/продающих):**
- Все поля из шаблона `templates/brief-template.md`

**Выход:** Итоговый бриф в формате:
```markdown
# Итог брифа

Тема: ...
Цель: ...
Аудитория: ...
Главная идея: ...
Ключевой конфликт: ...
Новая рамка: ...
Обязательные смыслы: ...
Ограничения: ...
Рекомендованный тон: ...
Следующий шаг: ...
```

### Этап 2: Research (Расхождение → Схождение)

**Задача:** Обогатить сценарий конкретными кейсами, цифрами, инсайтами.

**Принцип работы:** Расхождение (широкий поиск) → Схождение (безжалостный фильтр) → Интеграция (вставка в блоки).

**Правила:** См. `research-rules.md` в корне проекта.

#### Фаза 1: Расхождение (30 мин)

**Что ищем:**
1. **YouTube:** Конкурентные видео по теме (топ-5)
2. **Web:** Статьи, кейсы компаний, цифры
3. **Концепции:** Теории, исследования, цитаты экспертов

**Запросы (примеры):**
- "[тема] YouTube"
- "[тема] кейсы компаний примеры"
- "[тема] исследования статистика"
- Специфические концепции (если есть в брифе)

**Фиксация:**
Создаю `sessions/[project]/research-raw.md` с разделами:
- YouTube: конкурентные видео
- Веб: кейсы компаний
- Веб: концепции и теории
- Анти-паттерны (чего избегать)

**Критерий остановки:**
- 20+ источников найдено
- Или 30 мин прошло
- Или идеи начали повторяться

#### Фаза 2: Схождение (20 мин)

**Что делаем:**
1. Отбираю must-have инсайты (3-5 на каждый будущий блок)
2. Адаптирую в TOV Михаила
3. Определяю, куда вставить

**Критерии отбора must-have:**
- ✅ Конкретный кейс с именами и цифрами
- ✅ Контринтуитивная идея
- ✅ Авторитетная цитата
- ✅ Яркая метафора/аналогия
- ✅ Статистика, усиливающая аргумент

**Критерии never:**
- ❌ Банальности ("кризис — это возможность")
- ❌ Абстракции без действий
- ❌ Противоречия основному месседжу

**Фиксация:**
Создаю `sessions/[project]/research-insights.md` с таблицей:
```markdown
| Блок | Инсайт | Источник | Адаптация в TOV |
|------|--------|----------|-----------------|
| 1    | ...    | URL      | "Вот смотрите..." |
```

**Выход:**
```markdown
# Research Insights

## Блок 1: [Название]
### Must-have инсайт 1
**Источник:** [URL]
**Факт:** [Оригинал]
**Адаптация в TOV:** [Переписано в стиле Михаила]
**Где вставить:** [Конкретное место в блоке]

[... остальные блоки]
```

#### Фаза 3: Интеграция

Выполняется автоматически при генерации блоков (Этап 5).

**Важно:**
- Research делается ДО создания архитектуры
- Инсайты интегрируются В ПРОЦЕССЕ генерации блоков
- Не перегружать — 1-2 инсайта на блок максимум

### Этап 3: Сверка с эталоном Михаила

**Задача:** Определить, какой стиль и структура подходят.

**Процесс:**
1. Читаю `knowledge-base/TOV-analysis.md`
2. Читаю `knowledge-base/STRUCTURES-analysis.md`
3. Определяю:
   - Рекомендованный тон (на основе TOV)
   - 2-3 подходящие структуры (из 5 архитектур)
   - Риски по стилю
   - Что точно не делать

**Выход:**
```markdown
# Сверка с эталоном Михаила

## Рекомендованный тон:
- Прямой, без сглаживаний
- Через конкретные кейсы
- Метафоры из физического мира
- [Детали из TOV]

## Подходящие структуры:

### Структура 1: [Название]
**Почему подходит:** [обоснование]
**Риски:** [возможные проблемы]

### Структура 2: [Название]
**Почему подходит:** [обоснование]
**Риски:** [возможные проблемы]

## Рекомендация:
[Какую структуру лучше выбрать и почему]

## Что точно не делать:
- ❌ [Список анти-паттернов из TOV]
```

### Этап 4: Выбор структуры

**Задача:** Команда выбирает одну из предложенных структур.

**Процесс:**
1. Показываю 2-3 структуры с обоснованием
2. Команда выбирает одну
3. Если нужно — адаптирую структуру под задачу

---

### Этап 5: Архитектура видео

**Задача:** Разложить структуру на блоки с функциями.

**Процесс:**
1. Беру выбранную структуру
2. Раскладываю на блоки:

```markdown
# Архитектура видео: [Название структуры]

## Блок 1: Хук
**Функция:** Зацепить через узнаваемую проблему  
**Смысл:** [Что здесь должно быть]  
**Почему зритель смотрит дальше:** [Обещание]

## Блок 2: [Название]
**Функция:** ...
**Смысл:** ...
**Почему зритель смотрит дальше:** ...

[И так далее для всех блоков]
```

3. Команда утверждает архитектуру или корректирует

---

### Этап 6: Генерация сценария по блокам

**Задача:** Написать текст для каждого блока с интеграцией research-инсайтов.

**Процесс:**
1. Для каждого блока из архитектуры:
   - Проверяю `research-insights.md` — есть ли инсайты для этого блока
   - Пишу текст ведущего с интегрированными инсайтами
   - Указываю ключевую фразу
   - Объясняю, почему зритель продолжит смотреть
   - Проверяю TOV

2. **Правила интеграции research:**
   - Максимум 1-2 инсайта на блок
   - Адаптировать в TOV (использовать готовую адаптацию из research-insights.md)
   - Вставлять органично, не отдельным куском
   - Цифры и имена обязательны (если есть)

3. Формат блока (из `templates/block-template.md`):
```markdown
## Блок N: [Название]

**Функция:** [...]
**Задача:** [...]
**Текст ведущего:**
```
[Текст]
```
**Ключевая фраза:** > [...]
**Почему зритель продолжит смотреть:** [...]
**Проверка TOV:** ✅/❌ + замечания
**Статус:** `OK`
```

3. Генерирую блоки последовательно или все сразу (в зависимости от запроса)

---

### Этап 7: Оценка блоков

**Задача:** Команда ставит статусы каждому блоку.

**Статусы:**
- `OK` — берём как есть
- `EDIT` — мысль ок, переписать формулировку
- `WEAK` — блок слабый, нужен новый заход
- `CUT` — удалить
- `MOVE` — перенести в другой блок
- `NOT_TOV` — не похоже на Михаила
- `ADD_PROOF` — нужен пример/факт/кейс
- `ADD_ACTION` — не хватает практического действия
- `TOO_LONG` — слишком длинно
- `TOO_ABSTRACT` — слишком абстрактно

**Процесс:**
1. Команда проходит по блокам и ставит статусы
2. Оставляет комментарии к каждому блоку

**Инструмент:** HTML-интерфейс `review.html` для удобного ревью

---

### Этап 8: Переписывание проблемных блоков

**Задача:** Исправить блоки со статусом != OK.

**Правила обработки статусов:**

**`EDIT`** — Сохраняю смысл, переписываю формулировку:
- Убираю ИИ-штампы
- Делаю более прямым
- Добавляю конкретики

**`WEAK`** — Предлагаю 2-3 новых захода для блока

**`CUT`** — Удаляю блок, проверяю логику сценария

**`MOVE`** — Предлагаю, куда лучше перенести

**`NOT_TOV`** — Переписываю ближе к голосу Михаила (используя TOV-базу)

**`ADD_PROOF`** — Прошу кейс/факт или предлагаю, какой тип доказательства нужен

**`ADD_ACTION`** — Добавляю практический шаг для зрителя

**`TOO_LONG`** — Сокращаю до сути

**`TOO_ABSTRACT`** — Добавляю конкретики: цифры, примеры, кейсы

---

### Этап 9: Финальная сборка

**Задача:** Собрать финальный сценарий.

**Выход:**
1. **Финальный сценарий** — все блоки в правильном порядке
2. **Список ключевых фраз** — что должно запомниться
3. **Список блоков и их функций** — карта сценария
4. **Места для фактов/кейсов** (если остались)

---

### Этап 10: Визуальный слой

**Задача:** Создать смысловой бриф визуализации для монтажёра.

**Процесс:**
1. Читаю `knowledge-base/VISUAL-patterns-FINAL.md` (база паттернов канала)
2. Читаю финальный сценарий блок за блоком
3. Для каждого предложения:
   - Определяю **триггер визуализации**:
     - Метафора ("как пружина", "как страус")
     - Список ("3 шага", "4 типа")
     - Кейс компании ("Airbnb", "М.Видео")
     - Цифры/статистика ("20 млрд убытка")
     - Эмоция ("страх", "паника")
     - Концепция ("антихрупкость", "трансформация")
     - Ключевая фраза (главный месседж)
   - Матчу триггер → визуальный паттерн (из базы)
   - Описываю кадр через **ЧТО / ЗАЧЕМ / ПОЧЕМУ ЗДЕСЬ**

4. Для каждого кадра создаю:
   - **ЧТО:** Краткое описание визуала (композиция, объекты, движение)
   - **ЗАЧЕМ:** Какой смысл подчёркивает этот визуал
   - **ПОЧЕМУ ЗДЕСЬ:** Как усиливает речь Михаила в этот момент
   - **ПАТТЕРН:** Код из базы (A1, B2, F5 и т.д.)
   - **REFERENCER:** Концептуальное направление (не промпт, а идея)
   - **B-ROLL:** 3-4 конкретных варианта footage для монтажёра (если кадр это требует)
   - **АЛЬТЕРНАТИВА:** Другой подход (проще/сложнее), если применимо

**ПРАВИЛА визуализации:**

**✅ Описываю:**
- Композицию кадра (split-screen, overlay, PiP)
- Объекты и их действия (монолит трескается, пружина сжимается)
- Смысловую нагрузку (почему это работает)
- Цвета и формы (фиолетовый силуэт, белый текст на чёрном)
- Референс-направление (Kurzgesagt стиль, Netflix доки)
- **B-roll варианты** (3-4 конкретных источника footage + рекомендация)

**❌ НЕ описываю:**
- Одежду Михаила
- Причёску, аксессуары
- Детали внешнего вида
- Технические параметры анимации (keyframes, fps)

**Таблица триггеров → паттернов:**

| Триггер в тексте | Визуальный паттерн |
|------------------|-------------------|
| "3 шага", "4 типа" | B1 (Список через экран) или B4 (Анимированный прогресс) |
| Ключевая фраза | B2 (Текст на экране крупно) |
| "как пружина", метафора | F5 (Стильная анимация) или E1 (2D силуэт) |
| "Airbnb", кейс компании | D1 (B-roll) + C1 (Таблица с цифрами) |
| "20 млрд убытка", цифры | C1 (Таблица с метриками) |
| "страх", "паника", эмоция | F1 (Киношный футаж) или F5 (Метафора) |
| "мозг работает", наука | F2 (3D-рендер) |
| "Bennis говорил", цитата | F3 (Исторический коллаж) |
| Сравнение "X vs Y" | Split-screen или F6 (Рисованная анимация) |

**Формат выхода:** `visual-brief.md`

Структура:
```markdown
## БЛОК 1: Хук (0:00-3:00)

### Кадр 1: Вопрос | 0:00-0:15

**ЧТО:**
Михаил в кадре, чёрный фон. Смотрит прямо в камеру...

**ЗАЧЕМ:**
Прямой контакт с аудиторией. Вопрос заставляет мозг включиться...

**ПОЧЕМУ ЗДЕСЬ:**
Первые 3 секунды решают, останется зритель или нет...

**ПАТТЕРН:** A1 (Студийная говорящая голова)

**РЕФЕРЕНС:** Ted Talk вступление

---

### Кадр 2: Кейс М.Видео | 0:15-0:35

**ЧТО:**
Михаил говорит про убытки М.Видео. Поверх кадра — 
визуальные вставки.

**ЗАЧЕМ:**
Доказательство через реальный пример. Цифры без 
визуала не запоминаются.

**ПОЧЕМУ ЗДЕСЬ:**
Михаил называет конкретные цифры. Монтажёр должен 
показать их визуально в момент произнесения.

**ПАТТЕРН:** A1 (Говорящая голова) + C1 (Таблица с метриками)

**РЕФЕРЕНС:** Финансовые документалки CNBC

**B-ROLL (варианты для монтажёра):**
1. Фасад магазина М.Видео (stock footage, Pexels/Unsplash)
2. Логотип М.Видео анимированный (fade in/out)
3. График убытков: 7 млрд → 7.5 млрд → 20 млрд (моушн-графика, красная линия вниз)
4. Пустой магазин электроники (stock footage, Storyblocks)

**Рекомендация:** Вариант 2 + 3 (логотип + график). Короткий логотип 
(2 сек) → график появляется поверх говорящей головы (5 сек).

---

### Кадр 3: Ключевая фраза | 0:35-0:45

**ЧТО:**
Чёрный экран. Белый текст появляется по строкам...

**ЗАЧЕМ:**
Якорь запоминания. Фраза остаётся в голове...

**ПОЧЕМУ ЗДЕСЬ:**
Михаил дал неожиданный ответ. Текст усиливает эффект...

**ПАТТЕРН:** B2 (Текст на экране)

**РЕФЕРЕНС:** Netflix документалки — минимализм, крупный шрифт
```

**Проверка качества визуального слоя:**
- Каждая ключевая мысль визуализирована? ✓
- Метафоры превращены в конкретные образы? ✓
- Данные показаны через контраст (красный/зелёный)? ✓
- Есть навигация для длинных видео (>15 мин)? ✓
- Главный месседж повторяется визуально 2-3 раза? ✓

**Примечание:**
Визуальный слой создаётся ПОСЛЕ финального сценария. Это не сценарий — это инструкция для монтажёра/моушн-дизайнера о том, **что показывать и зачем**.

### Этап 11: Генерация хуков и названий (НОВЫЙ)

**Задача:** Создать 10 вариантов названия + 5 вариантов хука (первые 30 сек) для тестирования.

**Когда запускать:** После Этапа 9 (Финальная сборка) — хуки должны отражать готовый сценарий.

**Процесс генерации названий:**

1. Читаю финальный сценарий
2. Определяю ключевые элементы:
   - Главная мысль (core message)
   - Самая яркая метафора
   - Самая впечатляющая цифра
   - Главное противоречие
   - Ключевой кейс
3. Применяю 10 формул:

**10 формул названий:**

| Формула | Паттерн | Пример |
|---------|---------|--------|
| 1. Вопрос-провокация | "Почему [неожиданный факт]?" | "Почему кризис — это протокол, а не паника?" |
| 2. Предупреждение | "[Опасность], которая [последствия]" | "Ошибка, которая превратила убыток в 20 млрд" |
| 3. Трансформация | "Как [из плохого] в [хорошее] за [время]" | "От паники к протоколу за 4 шага" |
| 4. Цифра-шокер | "[Большая цифра], которая [эффект]" | "20 млрд убытка vs 186% роста: две реакции на кризис" |
| 5. Противоречие | "Почему [общепринятое] не работает" | "Почему 'переждать' — худшая стратегия" |
| 6. Простота | "[Тема] — просто о сложном" | "Антикризисный протокол: 4 шага вместо хаоса" |
| 7. Срочность | "Что делать, если [кризис] уже наступил" | "Кризис уже здесь: протокол первых 24 часов" |
| 8. Метафора | "[Яркая метафора]: [суть]" | "Пружина vs Монолит: две модели компании" |
| 9. Секрет | "Что [эксперты] знают о [тема]" | "Что Taleb знает об антихрупкости" |
| 10. Прямое обещание | "[Результат] — пошаговая инструкция" | "Антикризисный протокол: пошаговая инструкция" |

**Процесс генерации хуков:**

1. Читаю блок 1 сценария (хук)
2. Определяю:
   - Главная боль аудитории
   - Самый яркий факт
   - Самая сильная метафора
   - Контраст (до/после, успех/провал)
3. Применяю 5 формул:

**5 формул хуков:**

| Формула | Структура | Длительность |
|---------|-----------|--------------|
| 1. Вопрос-проблема | Вопрос → Усиление → Обещание | 20-25 сек |
| 2. Шокирующий факт | Цифра → Контекст → Вопрос → Обещание | 25-30 сек |
| 3. История-узнавание | Типичная ситуация → Последствия → "Знакомо?" → Выход | 30 сек |
| 4. Противопоставление | Два объекта → Ситуация → Разные результаты → "В чём разница?" | 30 сек |
| 5. Прямое обещание | Проблема → Решение → Формат → Как использовать | 25-30 сек |

**Критерии отбора названий:**
- ✅ Понятно, о чём видео
- ✅ Вызывает любопытство
- ✅ Не длиннее 60 символов
- ✅ Работает БЕЗ обложки

**Критерии отбора хуков:**
- ✅ Укладывается в 30 секунд (≈70-90 слов)
- ✅ Работает только на слух (не требует визуала)
- ✅ Обещание конкретное
- ✅ Плавный переход к основе

**Выход:** `hooks-variants.md`

Структура:
```markdown
## НАЗВАНИЯ (10 вариантов)
```

## TOV-правила для генерации

### Как писать в стиле Михаила:

**✅ Используй:**
- Конкретные кейсы с именами: "Саша Голцов", "Виктор Кузнецов"
- Цифры без округлений: "9.840 операций", "180 млрд"
- Метафоры из физического мира: "пуливеризатор", "гидрорезка"
- Вводные слова: "знаете", "понимаете", "вот"
- Повторы для усиления: "очень-очень", "прямо-прямо"
- Вопросы-промпты: "А что такое оборачиваемость?"
- Прямые формулировки: "больные модели", "палим деньги"

**❌ Не используй:**
- "В современном мире..."
- "Важно понимать, что..."
- "Позвольте мне пояснить..."
- "Следует отметить..."
- Пассивные конструкции
- Причастные обороты
- Disclaimer-ы
- Извинения за длину
- Сглаживания ("возможно, я ошибаюсь...")

**Структура речи:**
- Чередование коротких и длинных предложений
- Короткие — для акцента
- Длинные — для раскрытия контекста
- Паузы через "вот", "э"

**Обращение:**
- "Вы", "мы" (включающее)
- Редко "я" (только для личного опыта)

## Пример использования

### 1. Запуск
```
Пользователь: Нужен сценарий видео про антикризисный протокол
```

### 2. Брифование
```
Скилл: Я понял задачу так:
Тема: Антикризисный протокол для бизнеса
Цель: Дать практический порядок действий в кризисе
Аудитория: Предприниматели в кризисе

Что нужно уточнить:
1. Какая длительность видео?
2. Какие материалы уже есть?
3. Какое действие зритель должен сделать после?
```

### 3. Сверка с TOV
```
Скилл: Рекомендую:
- Прямой тон, без сглаживаний
- Через метафору "кризис = не паника, а протокол"
- Подходящие структуры:
  1. Протокол/Checklist (7 шагов)
  2. Хаос → Диагностика → Решение
```

### 4. Выбор структуры
```
Пользователь: Берём Протокол/Checklist
```

### 5. Архитектура
```
Скилл: Архитектура:
Блок 1: Хук — через ошибку "делать вид, что ничего не происходит"
Блок 2: Главная рамка — кризис = протокол, не паника
Блок 3-9: Шаги протокола
Блок 10: Финал — призыв к действию
```

### 6. Генерация блоков
```
Скилл: [Генерирует блоки по шаблону]
```

### 7. Редактура
```
Пользователь: Блок 3 — NOT_TOV, слишком гладко
Блок 5 — ADD_PROOF, нужен кейс
Блок 7 — OK
```

### 8. Финал
```
Скилл: [Собирает финальный сценарий]
```

## Ограничения MVP

**Не входит в MVP:**
- Deep research по теме
- Конкурентный анализ
- Монтажная карта
- Визуальный слой
- Интеграции лид-магнитов
- Автоматическое обучение на правках
- YouTube-статистика

Это можно добавить в полную версию.

## Метрики качества

**Хороший сценарий:**
- ✅ Все блоки со статусом OK
- ✅ Нет ИИ-штампов
- ✅ Есть конкретные кейсы/цифры
- ✅ Финал содержит действие для зрителя
- ✅ Похоже на Михаила (проверка по TOV)

**Плохой сценарий:**
- ❌ Абстрактные рассуждения без примеров
- ❌ Канцелярит, пассивные конструкции
- ❌ Нет призыва к действию
- ❌ Не звучит как Михаил
