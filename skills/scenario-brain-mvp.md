# Scenario Brain MVP — Сценарный скилл для видео Михаила Дашкиева

## Назначение

Система для создания сценариев видео в стиле Михаила Дашкиева через управляемый процесс:
- **Discovery-бриф** (5-7 мин) → **Research** → Сверка с TOV → Выбор структуры → Архитектура → **Генерация хуков** → Сценарий по блокам → Ревью → Правки → Финал → **Визуальный слой** → **Генерация названий**

**Главный принцип:** Не писать полный сценарий сразу, а вести команду по этапам.

**Версия:** 2.0 (Самодостаточный — встроены TOV и визуальные паттерны)

---

## Этапы работы MVP

### Этап 0: Discovery-interview бриф (НОВЫЙ)

**Задача:** Быстро и точно понять, что за видео делаем — через живой диалог, а не анкету.

**Принцип:** Следующий вопрос зависит от предыдущего ответа. Как в интервью.

**Процесс:**

1. **Определяю тип видео** (первый вопрос):
```
Какой тип видео мы делаем?
A. Обучающее (методология, протокол)
B. Продающее (вебинар, продукт, услуга)
C. Кейс (история компании)
D. Мотивационное (вдохновение, mindset)
E. Свой вариант
```

2. **Выбираю ветку вопросов** в зависимости от ответа.

**Формат каждого вопроса:**
```
[Вопрос]

Варианты:
- [Вариант 1]
- [Вариант 2]
- [Вариант 3]
- Свой вариант → [уточни]
```

**Важно:** ВСЕГДА предлагать варианты выбора + опцию "Свой вариант".

3. **Задаю общие вопросы** (для всех веток):
   - Целевая длина: 5-10 / 15-25 / 30-45 / 60+ / Не важно / Свой вариант
   - Источник контента: Транскрипт / Звонок / Тезисы / С нуля / Свой вариант
   - Ключевая фраза: [примеры] / Ещё не придумал / Свой вариант

4. **Собираю итоговый бриф** из ответов

**Полное дерево вопросов:** См. `templates/discovery-brief.md`

**Выход:**
```markdown
# Итоговый бриф (из discovery-interview)

**Тип:** Обучающее (протокол)
**Тема:** Антикризисный протокол
**Аудитория:** Собственники в кризисе
**Формат:** 4 шага, 40-45 мин
**Ключевая фраза:** "Кризис — это не паника. Это протокол."
**Доказательства:** М.Видео, Airbnb, кризис 2008
**Действие:** Скачать таблицу, заполнить, созвать совещание
**Источник:** Есть транскрипт
```

**Время:** 5-7 минут (вместо 30 минут статичной анкеты)

**Детали:** См. `templates/discovery-brief.md`

### Этап 1: Research (Расхождение → Схождение)

**Задача:** Обогатить сценарий конкретными кейсами, цифрами, инсайтами.

**Принцип работы:** Расхождение (широкий поиск) → Схождение (безжалостный фильтр) → Интеграция (вставка в блоки).

**Правила:** См. `research-rules.md` в корне проекта.

#### Фаза 1: Расхождение (30 мин)

**Что ищем:**
1. **YouTube:** Конкурентные видео по теме (топ-5)
2. **Web:** Статьи, кейсы компаний, цифры
3. **Концепции:** Теории, исследования, цитаты экспертов

**Запросы (примеры):**
- "[тема] YouTube"
- "[тема] кейсы компаний примеры"
- "[тема] исследования статистика"
- Специфические концепции (если есть в брифе)

**Фиксация:**
Создаю `sessions/[project]/research-raw.md` с разделами:
- YouTube: конкурентные видео
- Веб: кейсы компаний
- Веб: концепции и теории
- Анти-паттерны (чего избегать)

**Критерий остановки:**
- 20+ источников найдено
- Или 30 мин прошло
- Или идеи начали повторяться

#### Фаза 2: Схождение (20 мин)

**Что делаем:**
1. Отбираю must-have инсайты (3-5 на каждый будущий блок)
2. Адаптирую в TOV Михаила
3. Определяю, куда вставить

**Критерии отбора must-have:**
- ✅ Конкретный кейс с именами и цифрами
- ✅ Контринтуитивная идея
- ✅ Авторитетная цитата
- ✅ Яркая метафора/аналогия
- ✅ Статистика, усиливающая аргумент

**Критерии never:**
- ❌ Банальности ("кризис — это возможность")
- ❌ Абстракции без действий
- ❌ Противоречия основному месседжу

**Фиксация:**
Создаю `sessions/[project]/research-insights.md` с таблицей:
```markdown
| Блок | Инсайт | Источник | Адаптация в TOV |
|------|--------|----------|-----------------|
| 1    | ...    | URL      | "Вот смотрите..." |
```

**Выход:**
```markdown
# Research Insights

## Блок 1: [Название]
### Must-have инсайт 1
**Источник:** [URL]
**Факт:** [Оригинал]
**Адаптация в TOV:** [Переписано в стиле Михаила]
**Где вставить:** [Конкретное место в блоке]

[... остальные блоки]
```

#### Фаза 3: Интеграция

Выполняется автоматически при генерации блоков (Этап 5).

**Важно:**
- Research делается ДО создания архитектуры
- Инсайты интегрируются В ПРОЦЕССЕ генерации блоков
- Не перегружать — 1-2 инсайта на блок максимум

### Этап 2: Сверка с эталоном Михаила

**Задача:** Определить, какой стиль и структура подходят.

**Процесс:**
1. Читаю `knowledge-base/TOV-analysis.md`
2. Читаю `knowledge-base/STRUCTURES-analysis.md`
3. Определяю:
   - Рекомендованный тон (на основе TOV)
   - 2-3 подходящие структуры (из 5 архитектур)
   - Риски по стилю
   - Что точно не делать

**Выход:**
```markdown
# Сверка с эталоном Михаила

## Рекомендованный тон:
- Прямой, без сглаживаний
- Через конкретные кейсы
- Метафоры из физического мира
- [Детали из TOV]

## Подходящие структуры:

### Структура 1: [Название]
**Почему подходит:** [обоснование]
**Риски:** [возможные проблемы]

### Структура 2: [Название]
**Почему подходит:** [обоснование]
**Риски:** [возможные проблемы]

## Рекомендация:
[Какую структуру лучше выбрать и почему]

## Что точно не делать:
- ❌ [Список анти-паттернов из TOV]
```

2. Команда выбирает одну
3. Если нужно — адаптирую структуру под задачу

1. **Беру выбранную структуру** из Этапа 3

2. **Раскладываю на блоки** (обычно 8-12 блоков):

```markdown
# Архитектура видео: [Название структуры]

**Выбранная структура:** [имя из 5 архитектур]

**Функция:** Зацепить через узнаваемую проблему

**Смысл:** [Что здесь должно быть — детальное описание]

**Что здесь (контент):**
- [Конкретные элементы: вопрос, факт, кейс]
- [Research-инсайты для вставки]
- [Ключевые цифры/имена]

**Почему зритель смотрит дальше:** [Обещание / интрига]

**Ключевая фраза:** "[фраза из хука]"

---

## Блок 2: [Название] (3:00-8:00)

**Функция:** ...

**Смысл:** ...

**Что здесь (контент):**
- ...

**Почему зритель смотрит дальше:** ...

**Ключевая фраза:** ...

---

[... остальные блоки]
```

3. **ОБЯЗАТЕЛЬНО сохраняю** в `sessions/[project]/architecture.md`

4. **Показываю краткую структуру:**
```
Архитектура готова. Файл: sessions/[project]/architecture.md

11 блоков (~55 минут):
1. Хук (3 мин) — главная ошибка
2. Главная рамка (5 мин) — кризис = протокол
...

Переходим к Этапу 5 (Генерация хуков).
```

5. **СРАЗУ перехожу к Этапу 5** — не жду ОК, не спрашиваю разрешения.

### Этап 5: Генерация вариантов хука

**Задача:** Создать 5 вариантов хука (Блок 1, первые 30 секунд) — выбрать лучший → это станет началом сценария.

**Когда:** ПОСЛЕ архитектуры, ДО генерации остальных блоков.

**Зачем:** Хук определяет tone и энергию всего видео. Если он слабый — всё видео провалится.

**Процесс:**

1. **Читаю архитектуру Блока 1:**
   - Функция: Зацепить через узнаваемую проблему
   - Смысл: [что должно быть]
   - Обещание: [почему смотрят дальше]

2. **Читаю бриф:**
   - Тип видео (обучающее/продающее/кейс/мотивационное)
   - Аудитория (в какой ситуации)
   - Ключевая фраза

3. **Генерирую 5 вариантов хука** по 5 формулам:

**5 формул хуков:**

| Формула | Структура | Длительность | Когда использовать |
|---------|-----------|--------------|-------------------|
| 1. Вопрос-проблема | Вопрос → Усиление → Обещание | 20-25 сек | Обучающее, зритель уже в проблеме |
| 2. Шокирующий факт | Цифра → Контекст → Вопрос → Обещание | 25-30 сек | Есть впечатляющая цифра/кейс |
| 3. История-узнавание | Типичная ситуация → Последствия → "Знакомо?" → Выход | 30 сек | Зритель узнаёт себя в ситуации |
| 4. Противопоставление | Два объекта → Ситуация → Разные результаты → "В чём разница?" | 30 сек | Есть яркий контраст (успех vs провал) |
| 5. Прямое обещание | Проблема → Решение → Формат → Как использовать | 25-30 сек | Аудитория знает проблему, хочет решение |

4. **Для каждого варианта пишу:**
```markdown
### Хук 1: [Формула]

**Текст:**
"[Текст хука 70-90 слов]"

**Длительность:** X секунд

**Плюсы:**
- [Что работает]

**Минусы:**
- [Что может не сработать]
```

5. **Даю рекомендацию:** Какой хук лучше и почему.

6. **Команда выбирает** 1 вариант.

7. **После выбора хука СРАЗУ перехожу к Этапу 6** (генерация блоков) — не спрашиваю "Продолжить?".

**Критерии отбора:**
- ✅ Укладывается в 30 секунд (≈70-90 слов)
- ✅ Работает только на слух (не требует визуала для понимания)
- ✅ Обещание конкретное (не "узнаете много", а "получите 4 шага")
- ✅ Плавный переход к Блоку 2

**Выход:** `sessions/[project]/hooks-variants.md`

**Детали формул:** См. `templates/hooks-module.md`

### Этап 6: Генерация сценария по блокам

**Задача:** Написать текст для ВСЕХ блоков с интеграцией research-инсайтов.

**ВАЖНО:** Генерирую ВСЕ блоки за один раз, БЕЗ остановок на середине.

**Процесс:**

1. **Читаю:**
   - `sessions/[project]/architecture.md` — все блоки
   - `sessions/[project]/research-insights.md` — инсайты для вставки
   - `sessions/[project]/hooks-variants.md` — выбранный хук (это Блок 1)

2. **Для каждого блока (2-N) генерирую:**
   - Проверяю `research-insights.md` — есть ли инсайты для этого блока
   - Пишу текст ведущего с интегрированными инсайтами
   - Указываю ключевую фразу
   - Объясняю, почему зритель продолжит смотреть
   - Проверяю TOV

3. **Правила интеграции research:**
   - Максимум 1-2 инсайта на блок
   - Адаптировать в TOV (использовать готовую адаптацию из research-insights.md)
   - Вставлять органично, не отдельным куском
   - Цифры и имена обязательны (если есть)

4. **Формат блока:**
```markdown
## Блок N: [Название]

**Функция:** [...]
**Задача:** [...]
**Текст ведущего:**
```
[Текст]
```
**Ключевая фраза:** > [...]
**Почему зритель продолжит смотреть:** [...]
**Проверка TOV:** ✅/❌ + замечания
**Статус:** `OK`
```

5. **ОБЯЗАТЕЛЬНО генерирую ВСЕ блоки сразу:**
   - НЕ останавливаюсь на середине (например, 4 из 10)
   - НЕ спрашиваю "Продолжить?"
   - Генерирую все блоки сразу

6. **Сохраняю:**
   - `sessions/[project]/blocks-draft.md` — все блоки

7. **ПОКАЗЫВАЮ ВСЕ БЛОКИ ПОЛНЫМ ТЕКСТОМ В ЧАТЕ:**
   ```
   ## ✅ Все N блоков готовы
   
   ---
   
   ## Блок 1: [Название]
   
   **Текст ведущего:**
   [Полный текст блока...]
   
   **Ключевая фраза:** > [...]
   
   ---
   
   ## Блок 2: [Название]
   
   [И так далее для КАЖДОГО блока]
   ```

8. **СРАЗУ перехожу к Этапу 7** (Ревью) — жду статусов от команды.

**НЕ ПРЕРЫВАТЬСЯ** до полной генерации и показа всех блоков!

### Этап 7: Оценка блоков

**Задача:** Команда ставит статусы каждому блоку.

**Предусловие:** Все блоки УЖЕ ПОКАЗАНЫ полным текстом в чате (Этап 6, шаг 7).

**Статусы:**
- `OK` — берём как есть
- `EDIT` — мысль ок, переписать формулировку
- `WEAK` — блок слабый, нужен новый заход
- `CUT` — удалить
- `MOVE` — перенести в другой блок
- `NOT_TOV` — не похоже на Михаила
- `ADD_PROOF` — нужен пример/факт/кейс
- `ADD_ACTION` — не хватает практического действия
- `TOO_LONG` — слишком длинно
- `TOO_ABSTRACT` — слишком абстрактно

**Процесс:**

1. **Создаю HTML-интерфейс для ревью:**
   
   a) Читаю шаблон из `templates/review-html-template.html`
   
   b) Подготавливаю JSON-массив блоков:
   ```javascript
   [
       {title: "Хук", text: "Текст блока 1..."},
       {title: "Главная рамка", text: "Текст блока 2..."},
       // ... все блоки
   ]
   ```
   
   c) Заменяю плейсхолдеры в шаблоне:
   - `PROJECT_NAME_PLACEHOLDER` → название проекта
   - `BLOCKS_DATA_PLACEHOLDER` → JSON-массив блоков
   
   d) Сохраняю в `sessions/[project]/review.html`

2. **АВТОМАТИЧЕСКИ открываю в браузере:**
   ```bash
   open sessions/[project]/review.html
   ```

3. **Жду статусов от команды:**
   ```
   HTML-интерфейс открыт в браузере.
   
   После ревью отправь статусы в формате:
   
   Блок 1: OK
   Блок 2: EDIT — убрать повторы "вот смотрите"
   Блок 3: TOO_LONG — сократить на треть
   ...
   ```

4. **Записываю статусы** и перехожу к Этапу 8 (Правки)

### Этап 8: Переписывание проблемных блоков

**Задача:** Исправить блоки со статусом != OK.

**Правила обработки статусов:**

**`EDIT`** — Сохраняю смысл, переписываю формулировку:
- Убираю ИИ-штампы
- Делаю более прямым
- Добавляю конкретики

**`WEAK`** — Предлагаю 2-3 новых захода для блока

**`CUT`** — Удаляю блок, проверяю логику сценария

**`MOVE`** — Предлагаю, куда лучше перенести

**`NOT_TOV`** — Переписываю ближе к голосу Михаила (используя TOV-базу)

**`ADD_PROOF`** — Прошу кейс/факт или предлагаю, какой тип доказательства нужен

**`ADD_ACTION`** — Добавляю практический шаг для зрителя

**`TOO_LONG`** — Сокращаю до сути

**`TOO_ABSTRACT`** — Добавляю конкретики: цифры, примеры, кейсы

### Этап 9: Финальная сборка

**Задача:** Собрать финальный сценарий.

**Процесс:**
1. Собираю все блоки после правок
2. Проверяю логику переходов
3. Сохраняю в `sessions/[project]/scenario-final.md`

**Выход:**
1. **Финальный сценарий** — все блоки в правильном порядке
2. **Список ключевых фраз** — что должно запомниться
3. **Список блоков и их функций** — карта сценария

**После сборки СРАЗУ перехожу к Этапу 10** (Визуальный слой) — не спрашиваю разрешения.

### Этап 10: Визуальный слой

**Задача:** Создать смысловой бриф визуализации для монтажёра.

**ВАЖНО:** Визуализируем **НЕ блоками, а смысловыми фразами**.

**Процесс:**

1. **Читаю финальный сценарий** и разбиваю каждый блок на **смысловые фразы** (3-10 фраз на блок):
   - Одна фраза = одна мысль/образ/метафора/кейс
   - НЕ по предложениям (одна мысль может быть 2-3 предложения)
   - Каждая фраза = кандидат на визуализацию

2. **Для каждой фразы определяю:**
   - Нужна ли визуализация? (Да, если есть триггер)
   - Триггер визуализации:
     - Метафора ("как пружина", "как страус")
     - Список ("3 шага", "4 типа")
     - Кейс компании ("Airbnb", "М.Видео")
     - Цифры/статистика ("20 млрд убытка")
     - Эмоция ("страх", "паника")
     - Концепция ("антихрупкость", "трансформация")
     - Ключевая фраза (главный месседж)
   - Матчу триггер → визуальный паттерн (из базы)

3. **Для каждой визуализируемой фразы создаю кадр:**
   - **ФРАЗА:** Текст Михаила (буквально)

**3. Речевые конструкции**
- Вводные слова: "знаете", "понимаете", "вот"
- Повторы для усиления: "очень-очень", "прямо-прямо"
- Вопросы-промпты: "А что такое оборачиваемость?"
- Контраст: "А вот, например..."
- Обобщение: "В общем..."
- Переход: "Итак..."

**4. Прямые формулировки**
- "больные модели"
- "палим деньги"
- "шаблонное мышление"
- "пустые вложения"

**5. Структура речи**
- Короткие предложения для акцента: "Да, поэтому нам не всё равно, куда бить."
- Длинные для раскрытия: "Правильный капекс в том, что он создаёт преимущество на уровне бизнес-модели."
- Нумерация: "первое", "второе", "третье"
- Рамки в начале: "Сегодня поговорим про..."
- Итоги: "Итак, что мы узнали..."

**6. Обращение**
- "Вы", "мы" (включающее)
- Редко "я" (только для личного опыта/кейса)

**❌ НЕ ИСПОЛЬЗУЙ:**
- "В современном мире..."
- "Важно понимать, что..."
- "Позвольте мне пояснить..."
- "Следует отметить..."
- Пассивные конструкции ("было сделано")
- Причастные обороты ("находящиеся в состоянии")
- Disclaimer-ы ("возможно, я ошибаюсь...")
- Извинения ("извините за длинное объяснение")

1. "Главное часто выглядит очень скучно и даже банально. Например, добиться маржинальности 35% или, например, сократить затраты."

2. "То есть если рубль на входе, есть 3 руб. на выходе или X на выходе в определённом цикле времени."

3. "Палим деньги на проекты, на инициативы, на задачи, которые так никогда и не будут доведены до ума."

4. "Хватаемся за всё подряд, делаем вообще не то и не так. Суетимся, перескакиваем с одного на другое, делаем это поверхностно."

## Быстрые команды

**Для запуска:**
```
/scenario-brain [тема]
```

**Для перехода между этапами:**
- `/brief` — вернуться к брифу
- `/tov` — показать TOV-рекомендации
- `/structure` — выбрать структуру
- `/blocks` — сгенерировать блоки
- `/edit [номер блока]` — редактировать блок
- `/finalize` — собрать финал

## Пример использования

### 1. Запуск
```
Пользователь: Нужен сценарий видео про антикризисный протокол
```

### 2. Брифование
```
Скилл: Я понял задачу так:
Тема: Антикризисный протокол для бизнеса
Цель: Дать практический порядок действий в кризисе
Аудитория: Предприниматели в кризисе

Что нужно уточнить:
1. Какая длительность видео?
2. Какие материалы уже есть?
3. Какое действие зритель должен сделать после?
```

### 3. Сверка с TOV
```
Скилл: Рекомендую:
- Прямой тон, без сглаживаний
- Через метафору "кризис = не паника, а протокол"
- Подходящие структуры:
  1. Протокол/Checklist (7 шагов)
  2. Хаос → Диагностика → Решение
```

### 4. Выбор структуры
```
Пользователь: Берём Протокол/Checklist
```

### 5. Архитектура
```
Скилл: Архитектура:
Блок 1: Хук — через ошибку "делать вид, что ничего не происходит"
Блок 2: Главная рамка — кризис = протокол, не паника
Блок 3-9: Шаги протокола
Блок 10: Финал — призыв к действию
```

### 6. Генерация блоков
```
Скилл: [Генерирует блоки по шаблону]
```

### 7. Редактура
```
Пользователь: Блок 3 — NOT_TOV, слишком гладко
Блок 5 — ADD_PROOF, нужен кейс
Блок 7 — OK
```

### 8. Финал
```
Скилл: [Собирает финальный сценарий]
```

## Ограничения MVP

**Не входит в MVP:**
- Deep research по теме
- Конкурентный анализ
- Монтажная карта
- Визуальный слой
- Интеграции лид-магнитов
- Автоматическое обучение на правках
- YouTube-статистика

Это можно добавить в полную версию.

## Метрики качества

**Хороший сценарий:**
- ✅ Все блоки со статусом OK
- ✅ Нет ИИ-штампов
- ✅ Есть конкретные кейсы/цифры
- ✅ Финал содержит действие для зрителя
- ✅ Похоже на Михаила (проверка по TOV)

**Плохой сценарий:**
- ❌ Абстрактные рассуждения без примеров
- ❌ Канцелярит, пассивные конструкции
- ❌ Нет призыва к действию
- ❌ Не звучит как Михаил
