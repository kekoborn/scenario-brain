# scenario-brain: два режима + апгрейды пайплайна

**Дата:** 2026-06-12
**Статус:** спека утверждена, готова к плану реализации
**Источник:** разбор звонка с командой М. Дашкиева (обратная связь по scenario-brain)

## Контекст и проблема

Текущий scenario-brain — линейный пайплайн: discovery → research → TOV → структура →
архитектура → хуки → блоки → HTML-ревью → правки → финал → визуальный слой → название →
выдача DOCX+HTML. «Холодный старт» без материала обслуживается анкетой-интервью (ветка B).

На звонке команда попросила, чтобы ИИ был не интервьюером-анкетой, а **участником
мозгоштурма**: сам ресёрчил, кидал направляющие идеи, ловил живой штурм команды и
структурировал его. Плюс ряд апгрейдов самого сценарного потока.

## Решение (обзор)

Добавляем **режим выбора при старте** и **режим A (Брейншторм)** перед существующим
сценарным потоком (режим B), который тоже прокачиваем.

### Вход — Этап −1 (новый)

При `/scenario-brain` — вопрос кнопкой (AskUserQuestion):
- **«Брейншторм с нуля»** (материала нет) → режим A → впадает в режим B.
- **«Есть материал → сразу сценарий»** → режим B (текущая ветка A: лёгкий бриф по материалу).

Это заменяет нынешнее авто-ветвление A/B внутри Этапа 0.

### Режим A — Брейншторм (новые этапы A0–A4, только для «с нуля»)

- **A0. Импульс + ресёрч.** ИИ берёт тему, делает быстрый ресёрч (по `research-rules.md`)
  и выдаёт 5–10 направляющих идей / провокаций / развилок — как участник штурма, не анкета.
- **A1. Сбор живого штурма.** Команда штурмит на звонке (параллельная транскрибация уже
  идёт у них) и **вставляет текст блоками** в чат. ИИ принимает чанки. **Аудио-записи/Whisper
  внутри скилла НЕТ** — вход только текстом.
- **A2. Разбор на единицы идей.** ИИ режет всё (свои идеи + вставленный текст) на атомарные
  «единицы идей» и разворачивает/дополняет пул до десятков-сотни.
- **A3. Голосование** в HTML (общий механизм, см. ниже): по каждой единице — «берём /
  может быть / не берём» + поле комментария.
- **A4. Конфигурация.** Отобранные единицы ИИ группирует по смыслу → сценарные рамки/главы.
  Это вход в режим B (заменяет/наполняет бриф + первичный реестр единиц смысла).

### Режим B — Сценарий (существующий поток + апгрейды)

1. **Структура «единица смысла».** Блок = `Название → Главная мысль → единицы смысла (атомы)`.
   - HTML-ревью (Этап 7) переезжает с уровня «блок целиком» на уровень **единиц**: по
     каждой единице — голос (надо / может / не надо / переписать) + раскрытие в расшифровку.
   - Сначала согласуем скелет тезисов (какие единицы вообще нужны), потом формулировки.
   - При переписывании ИИ помечает, какие мысли обязательны, чтобы ключевое не терялось.

2. **Идеи визуализации inline.** При генерации каждой единицы ИИ **сразу** прикладывает
   идею визуала (короткое поле «визуал: …»), не дожидаясь Этапа 10. Этап 10 (визуальный
   слой) дочищает и достраивает, а не порождает с нуля.

3. **Чек-лист-артефакт (протокол).** Справа в ревью/сториборде накапливается конкретный
   тематический протокол: рубленые пункты «Чек — договориться по аренде», «Чек — список
   на увольнение», набивается по блокам. Инструктивный, не абстрактный.

4. **Двойная выдача (Этап 12).** Два формата сценария:
   - **Суфлёр** — DOCX слово-в-слово для чтения с телепромптера.
   - **Опорный/тезисный** — сжатые опорные тезисы (DOCX/MD).
   - Переключаемо **по-блочно** (один блок суфлёром, другой опорным — тестировать, что
     удобнее снимать).
   - Суфлёр генерируется НЕ копипастом системного текста: ИИ вытаскивает ключевую
     мысль/смысл и дорабатывает (прирезает, но смысл сохраняет).

5. **Вычитка (новый проход перед выдачей).** Отдельный шаг: орфография/грамматика +
   корректная терминология (напр. «твёрдые/гибкие расходы» → «постоянные/переменные») +
   связность метафор (если метафору убрали — убрать ссылки на неё во всех блоках).

### Общий механизм голосования (переиспользуемый)

Один HTML-компонент «список пунктов → голос по каждому» используется и в режиме A
(пул идей), и в режиме B (ревью единиц смысла). Единый UX, машиночитаемый вывод (JSON),
автосохранение в localStorage, кнопка «Скопировать ответы». Базируется на текущем
`templates/review-html-template.html`, обобщённом до «единицы» вместо «блока».

## Вне текущей итерации (зафиксировано, не делаем сейчас)

- ТЗ для монтажёра из **уже отснятого** видео и расстановка элементов поверх записи.
- «Клуб»/копилка кейсов и лог правок для дообучения агента.

Это следующая фаза.

## Затрагиваемые артефакты

- `SKILL.md` — новый Этап −1, блок этапов A0–A4, правки Этапов 7/10/12, новый шаг вычитки.
- `templates/review-html-template.html` — обобщить до «единицы» + режим пула идей + панель
  чек-листа справа.
- `templates/build_docx.py` — поддержка двух форматов (суфлёр / опорный), переключение по
  блокам.
- `templates/` — возможно новый шаблон под пул идей брейншторма (или параметр существующего).
- `templates/discovery-brief.md` — стыковка с режимом A (что собираем интервью, что —
  штурмом).

## Критерии готовности

- При старте можно выбрать брейншторм или сценарий-по-материалу.
- Режим A: ИИ выдаёт направляющие идеи + ресёрч, принимает вставленные блоки, режет на
  единицы, даёт проголосовать, конфигурирует в главы.
- Ревью идёт на уровне единиц смысла с голосованием; viz-идея есть у единиц уже на ревью.
- Чек-лист-артефакт накапливается по блокам.
- Выдача даёт суфлёр и опорный формат, переключаемо по блокам.
- Перед выдачей проходит вычитка (грамматика + термины + связность метафор).
- Общий механизм голосования один на оба режима.
