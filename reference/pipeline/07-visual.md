# Плейбук Э7: Визуальный слой (storyboard) + название

**Входы:** вычитанный `scenario-final.md` (`06-preflight.md`, Этап 9.5).
**Выходы:** `sessions/[project]/assets.md` (манифест материалов), `sessions/[project]/assets/`
(превью), `sessions/[project]/storyboard.html`, `sessions/[project]/titles-variants.md` с блоком
«✅ ВЫБРАНО».
**Гейт выхода:** борд прошёл самопроверку (образ не натянут / не пропущен там, где нужен);
под каждым названным реальным объектом — реальные кликабельные материалы, не «где искать»;
название выбрано и доработано с пользователем — это последний содержательный этап перед
выдачей документов (`08-delivery.md`).

---

## Этап 10: Визуальный слой (storyboard.html)

**Задача:** под каждый смысл сценария дать монтажёру/дизайнеру два слоя — КОНКРЕТНЫЙ ОБРАЗ (где
уместен) + РЕАЛЬНЫЕ МАТЕРИАЛЫ ПАЧКОЙ (сама картинка + ссылка). Не «референс-вайб» и не
схематичные мокапы — образ словами + реально найденные файлы. Модель **материалы-first**.

**Три шага: 10.1 единицы → 10.2 образ (с самопроверкой) → 10.3 материалы пачкой.**

---

### 10.1 — Разбивка на смысловые единицы

Прохожу `scenario-final.md` и режу на атомарные **смысловые единицы** (одна мысль/образ/кейс =
одна единица; 3–10 на блок). Каждая получает карточку в борде: `id · таймкод · смысл`.

---

### 10.2 — Образ под смысл (с самопроверкой субагентом)

**ОБРАЗ, а не иконка/список.** Под каждую единицу предлагаю КОНКРЕТНЫЙ ОБРАЗ — сцену (человек +
место + действие) или физическую метафору, читаемую без слов. Иконки, текст-карточки и списки —
обеднённый «очевидный» визуал; список/титр оставляю ТОЛЬКО для реально перечислимого (шаги,
чек-лист, рекап, CTA) и чистых титров.

**Рецепт «литерал → образ» (для КАЖДОЙ единицы):**
1. Сформулируй абстракцию одной фразой.
2. Спроси: «Как это выглядит в физическом мире? Какой ОДИН кадр делает мысль мгновенно
   понятной?»
3. Возьми образ из банка ниже ИЛИ придумай свежий (банк — не потолок).
4. Зафиксируй: `idea` (1–2 строки — что в кадре) + опц. ген-промпт (свет/оптика/камера) под
   Runway/Kling/Midjourney.

**Банк образов (тип смысла → образ):**

| Тип смысла | Образ |
|---|---|
| Выбор / развилка | человек на перепутье, тропы в разные исходы |
| Рост под давлением | росток сквозь асфальт; мышца под нагрузкой |
| Хаос / паника | фигура среди пожаров; шторм, качка |
| Фокус / приоритет | снайпер; прожектор выхватывает один объект из тьмы |
| Утечка / потеря | дырявый бак/ведро; песок сквозь пальцы |
| Срочность / окно | закрывающаяся дверь возможностей |
| Трансформация / закалка | горнило: металл → клинок; феникс |
| Прозрение | снять повязку/очки; страус поднимает голову |
| Изоляция / защита | щит; сейф; кофердам |
| Невидимая проблема | айсберг; трещина под глянцем |
| Хрупкое/устойчивое/антихрупкое | стакан / камень / мышца под грузом |
| Распределение | сортировка по корзинам; весы; бак с трубами |

Банк открыт — нет образа в банке, изобретаю по рецепту, а не подменяю списком.

**Самопроверка (обязательна — приём «сделал для всех → проверил субагентом»):** сначала
набрасываю образ для ВСЕХ единиц, затем прохожу проверяющим субагентом (`Task`, роль
«креативный директор»): по каждой единице — «нужен ли отдельный визуал или хватит говорящей
головы/титра? образ читается или натянут?». Возвращает только спорные:
- **FORCED** — образ натянут/очевиден/не читается → упростить или сделать говорящей головой.
- **MISSED** — помечено «голова», а смысл просится в сильный образ → дать образ.

Цель — образ ТАМ, где усиливает, а не везде. Списки/рекапы/CTA/чистые титры честно остаются
говорящей головой. (Если субагент недоступен в окружении — провожу аудит сам по тем же двум
критериям.)

---

### 10.3 — Сбор материалов ПАЧКОЙ (ядро) ⭐

Под каждую единицу, где назван **реальный объект** (компания, бренд, человек, продукт, книга,
цифра-из-СМИ), иду в веб и собираю МАКСИМУМ реальных материалов. В борде — **сама картинка +
ссылка на источник**, а не «где взять».

**Что собираю под тип якоря (собирать ВСЕ доступные):**

| Якорь | Материалы |
|---|---|
| Компания / бренд | лого · **скрин сайта** · продукция/витрина · фото магазина |
| Люди компании | фото **ВСЕХ** собственников/сооснователей (не одного!) |
| Эксперт / автор цитаты | фото человека · обложка книги/скрин публикации |
| Цифра / кейс из СМИ | **скрин конкретной статьи-первоисточника** (не домен) |

**Рецепты получения встраиваемых картинок (прямой URL → в борд):**
- **Лого:** `https://logo.clearbit.com/<домен>` (PNG).
- **Скрин сайта/статьи:** mShots — `https://s.wordpress.com/mshots/v1/<URL-encoded>?w=600`
  (рендерит скриншот любой страницы по URL). Так показываем сайт компании, витрину-через-сайт и
  скрин статьи-пруфа.
- **Фото человека:** Wikimedia Commons (прямой `upload.wikimedia.org/...` + лицензия) для
  публичных персон; иначе фото из публичного СМИ (og:image статьи) или скрин профильной статьи
  через mShots.
- **Обложка книги/товар:** прямой URL картинки с маркетплейса/издателя (og:image/галерея).

**Правила:**
- Несколько сооснователей → показываем ВСЕХ (прямым фото где есть, иначе скрин профильной
  статьи на каждого/совместной).
- Цифра/кейс — только с **конкретной** статьёй-первоисточником (URL+дата); скрин этой страницы
  = пруф. Нет живого источника → **флаг ⚠️ на реверификацию**, не выдавать за факт (гейт
  `research-rules.md`; ср. кейс Trend Surfers в эталоне — исходный Forbes 404, факты не
  подтверждены живым поиском → под флагом).
- Фото людей — только публичные СМИ/Commons со ссылкой; приватные соцпрофили не берём.
- Чем больше валидных материалов под единицу — тем лучше (монтажёру есть из чего выбрать).
- Складываю в `assets.md` (манифест: единица → тип → URL картинки → источник → статус); превью
  качаю в `sessions/[project]/assets/` (в обычном окружении).

**Не делаю:** не рисую финальную картинку за команду; не гоняю внешние реф-базы кадров (Shot
Cafe/Film Grab и пр. — из ядра убраны); не оставляю «где искать» вместо самой ссылки.

---

### Выдача — `storyboard.html` (материалы-first)

Собираю борд из `templates/storyboard-template.html`. По единице: **смысл** → **образ** (или
«говорящая голова/титр») → **галерея реальных материалов** (кликабельная картинка + подпись +
тип + ссылка-источник). Фильтры: Все / ⭐ Ключевые / 📎 С материалами / по блокам. Битые превью
деградируют в «открыть источник». Сохраняю `sessions/[project]/storyboard.html` → `open`.

**Формат единицы (`U`-массив в шаблоне):**
```javascript
{id:"4.5", b:4, t:"15:20–16:30", star:1,
 s:"12 STOREEZ занял нишу ушедших премиум-брендов",
 img:{idea:"вешалка: лого ушедших брендов сменяются на 12 STOREEZ", prompt:"…(опц., свет/оптика)"},
 // либо без образа:  img:null, talk:"титр / говорящая голова — что на экране"
 mats:[{src:"<URL картинки>", link:"<источник>", cap:"подпись", kind:"лого|сайт|сооснователь|статья|обложка", cover:1}],
 flag:"⚠️ … (если кейс на реверификации)"}
```

**Проверка качества:**
- Под каждую названную компанию — лого + скрин сайта + фото ВСЕХ собственников? ✓
- Цифра/кейс — конкретная статья-первоисточник (не домен), скрин-пруф? ✓
- Образ стоит там, где усиливает, и НЕ навязан спискам/рекапам (прошло самопроверку)? ✓
- Материалы — реальные кликабельные картинки + ссылки, не «где искать»? ✓
- Неподтверждённое — под флагом ⚠️, не выдано за факт? ✓

**Выход:** `assets.md` (манифест материалов) + `storyboard.html`.

**После визуального слоя СРАЗУ перехожу к Этапу 11** (Генерация названий) — не спрашиваю
разрешения.

---

## Этап 11: Название — генерация, выбор и доработка (последний смысловой этап)

**Задача:** Создать варианты названия, помочь выбрать ОДНО и довести его до финала. Это
последний содержательный этап перед выдачей документов.

**Когда запускать:** В самом конце — после финального сценария И визуального слоя. Название
опирается на готовый сценарий целиком.

**Процесс:**

1. Читаю финальный сценарий.
2. Определяю ключевые элементы: главная мысль (core message), самая яркая метафора, самая
   впечатляющая цифра, главное противоречие, ключевой кейс.
3. Применяю 10 формул:

| Формула | Паттерн | Пример |
|---------|---------|--------|
| 1. Вопрос-провокация | "Почему [неожиданный факт]?" | "Почему кризис — это протокол, а не паника?" |
| 2. Предупреждение | "[Опасность], которая [последствия]" | "Ошибка, которая превратила убыток в 20 млрд" |
| 3. Трансформация | "Как [из плохого] в [хорошее] за [время]" | "От паники к протоколу за 4 шага" |
| 4. Цифра-шокер | "[Большая цифра], которая [эффект]" | "20 млрд убытка vs 186% роста: две реакции на кризис" |
| 5. Противоречие | "Почему [общепринятое] не работает" | "Почему 'переждать' — худшая стратегия" |
| 6. Простота | "[Тема] — просто о сложном" | "Антикризисный протокол: 4 шага вместо хаоса" |
| 7. Срочность | "Что делать, если [кризис] уже наступил" | "Кризис уже здесь: протокол первых 24 часов" |
| 8. Метафора | "[Яркая метафора]: [суть]" | "Пружина vs Монолит: две модели компании" |
| 9. Секрет | "Что [эксперты] знают о [тема]" | "Что Taleb знает об антихрупкости" |
| 10. Прямое обещание | "[Результат] — пошаговая инструкция" | "Антикризисный протокол: пошаговая инструкция" |

**Критерии отбора:**
- Понятно, о чём видео
- Вызывает любопытство
- Не длиннее 60 символов (для превью YouTube)
- Работает БЕЗ обложки

**Выход:** `sessions/[project]/titles-variants.md`:
```markdown
## НАЗВАНИЯ (10 вариантов)

### Вариант 1: [Формула]
**Название:** "..."
**Плюсы:** ...
**Минусы:** ...

[...9 остальных]

---

## РЕКОМЕНДАЦИИ
**Топ-3 для A/B теста:** ...
**Обоснование:** ...
```

**ВЫБОР И ДОРАБОТКА (обязательно, не пропускать):**
4. Показываю варианты и даю рекомендацию (топ-3 по силе крючка).
5. Пользователь выбирает одно название (или просит другой заход — например «более
   кликбейтные»; тогда генерирую новую пачку под запрос и снова предлагаю).
6. Дорабатываю выбранное вместе с пользователем до финальной формулировки.
7. Фиксирую выбранное название отдельным блоком «✅ ВЫБРАНО» в `titles-variants.md` — именно
   оно пойдёт в заголовок документов на Этапе 12 (`08-delivery.md`).

**Детали формул:** `templates/hooks-module.md` (раздел «Генерация названий»).
