# Плейбук Э6: Предсдача (preflight) → ревью клиента → финал

**Входы:** staging `sessions/[project]/.blocks-vNN/*.md` (все блоки, `05-writing.md`);
`avatar.md`, `tov.md`, `facts.md`, `client-edits.md`.
**Выходы:** `reports/preflight-vNN.md`; `review.html` (открыт клиенту только после зелёного
отчёта); пополненный `client-edits.md`; `scenario-final.md` — вычитанный, прошедший юмор-проход
и гейт antislop.
**Гейт выхода:** Уровень 1 (скрипты) зелёный И Уровень 2 (4 агента) — 0 blocker у misha-review →
можно показывать клиенту (Этап 7). После ревью клиента → Этап 8 (переписывание по client-edits.md)
→ Этап 9 (сборка) → Этап 9.5 (вычитка, обязательна перед выдачей — `07-visual.md`/`08-delivery.md`).

**Не показывать клиенту сырое, непрогнанное через предсдачу.** Это конвейер с приёмкой на
выходе: гейты-документы (avatar/tov) задают контекст, но качество гарантируют проверки
результата — скрипты и агенты-аудиторы ДО показа, а не инструкции модели во время генерации.

---

## Уровень 1 — Скрипты (машинные гейты)

```bash
python3 reference/scripts/preflight.py --project <slug> [--staging .blocks-vNN] [--report] [--write]
```

Без `--staging` берёт последнюю по алфавиту папку `.blocks-vNN` в `sessions/<slug>/`.

**Гейты (все читают staging, не рабочие файлы):**
- **Г1 комплектность** — все N блоков на месте, ни один короче 200 символов (обрубленная генерация).
- **Г2 дубли** — попарное сравнение текста блоков (`difflib`), совпадение >35% — подозрение на
  копипаст между блоками.
- **Г3 стоп-слова** — по каталогу `reference/stop-words.md` (таблица `паттерн · тип · severity ·
  почему`); `blocker` валит гейт, `minor` только считается.
- **Г4 стоп-имена** — по `reference/stop-names.md` (список + фолбэк — фамилии из таблицы).
- **Г5 вводные** — блок не должен начинаться с «Смотрите/Давайте/А теперь/И вот что».
- **Г6 интеграции ≤2** — коммерческие вставки/лид-магнит помечены плашкой `[ИНТЕГРАЦИЯ` и их
  не больше двух на весь сценарий.
- **Хронометраж** — суммарные слова / темп чтения (по умолчанию 145 слов/мин) против целевой
  длины — информационно, не blocker сам по себе, но сигнал резать.

**Флаги:**
- `--report` — пишет `sessions/<slug>/reports/preflight-<staging>.md` с полным логом гейтов.
- `--write` — собирает `scenario-clean-<staging>-draft.md` **ТОЛЬКО при зелёных гейтах**. Это
  намеренная защита: раньше блоки дважды молча пропадали из воркфлоу и затирали рабочие файлы —
  скрипт не пишет ничего, пока хоть один гейт красный.
- Код выхода: `0` = всё зелёное, `1` = есть blocker.

**Сборка (`scenario-final.md`, суфлёр) — ТОЛЬКО после зелёных гейтов Уровня 1.** Красный гейт
на Уровне 1 останавливает конвейер раньше, чем до текста доберутся агенты Уровня 2 — дешевле
чинить дубли/стоп-слова скриптом, чем гонять на них дорогих аудиторов.

## Уровень 2 — Агенты-аудиторы (4 параллельно, все `model: sonnet`)

Запускаются одной волной (fan-out), каждый читает свою спеку целиком из `reference/agents/` и
возвращает JSON-вердикт по контракту, описанному в самом файле спеки. Не переписывают текст —
только диагностируют.

- **`misha-review`** (`reference/agents/misha-review.md`) — эмулятор разбора самого Михаила:
  читает гейты + `client-edits.md` + `facts.md`, идёт по сценарию поблочно и ловит его реальные
  претензии (реестр из 20 правил: выдуманные детали, стоп-имена, «ты», теория без примера,
  метафоры без продуха и т.д.). **Порог сдачи — 0 blocker.** Пока есть хоть один — клиенту не
  показываем.
- **`fact-verifier`** (`reference/agents/fact-verifier.md`) — адверсариальный верификатор
  фактуры: пытается ОПРОВЕРГНУТЬ каждую цифру/имя/кейс сценария сверкой с `facts.md` и
  первоисточником (не `summary.md` — запрещённый источник). При сомнении факт считается
  неподтверждённым.
- **`suffler-auditor`** (`reference/agents/suffler-auditor.md`) — «диктор»: читает суфлёр вслух
  «внутренним голосом» и ловит всё, обо что спотыкается язык — скороговорки, слишком длинные
  периоды без вдоха, несостыковки по тексту, висячие ссылки на вырезанное, неудобные для чтения
  числа.
- **`tov-auditor`** (`reference/agents/tov-auditor.md`) — сверяет сценарий ТОЛЬКО с правилами
  из гейтов `avatar.md`/`tov.md` (не выдумывает своих предпочтений): обращение на «вы», регистр,
  метафоры несущие и не подряд, перечисления без вложенности, стоп-термины, тон по типам блоков.

Все четыре сверяются с `client-edits.md` §D перед претензией к формулировке — дословные слова
клиента неприкосновенны, претензию к ним не выставлять (misha-review формально может похвалить
чистый блок — не обязан находить нарушения ради количества).

**Обучение:** после каждого реального разбора клиента реестр претензий `misha-review.md`
пополняется тем, что предсдача пропустила — метрика конвейера: ловить ≥80% претензий клиента
ДО показа.

## Уровень 3 — Отчёт

`reports/preflight-vNN.md` собирает: лог гейтов Уровня 1 + вердикты всех 4 агентов Уровня 2
(blocker/minor по каждому). Правило: **клиенту не показываем, пока отчёт не зелёный** — 0
blocker и по скриптам, и по всем агентам. После реального разбора клиента — обязательно
пополнить реестр претензий `reference/agents/misha-review.md` пропущенным пунктом, иначе
конвейер не учится.

## Этап 7: Оценка блоков (HTML-ревью)

**Предусловие:** отчёт предсдачи зелёный (Уровень 3 выше). Блоки НЕ показаны текстом в чате —
их полный текст пользователь читает в HTML-ревью.

**ВАЖНО: блоки ВСЕГДА выдаются пользователю через HTML-артефакт** (`review.html` из
канонического шаблона `templates/review-html-template.html`), а НЕ текстом в чате. Это
единственный способ показа: единый стиль у всех пользователей, удобный интерфейс чтения и
оценки, машиночитаемый вывод (JSON). Шаблон править только централизованно (он общий для всех
проектов); под конкретный сценарий менять только плейсхолдеры.

**Структура единицы смысла.** Блок раскрывается как `Название → Главная мысль → единицы
смысла`. Каждая единица — атом (одна мысль/образ/кейс) с полями: `mainThought` (относится к
главной мысли блока?), `text` (формулировка), `transcript` (раскрытие, опционально), `viz`
(идея визуала, из `05-writing.md`, Этап 6), `checklist` (пункт чек-листа, если единица его
порождает).

**Ревью идёт по единицам, а не по блокам целиком.** В `review.html` (`MODE="review"`) каждая
единица получает голос (надо / может / не надо / переписать) + комментарий. Сначала согласуем
скелет — какие единицы вообще нужны, потом формулировки.

**Статусы (код для ИИ ↔ подпись на русском для пользователя).** Пользователь видит ТОЛЬКО
русские подписи, коды нужны для машинной обработки:
- `OK` → «Оставить как есть»
- `EDIT` → «Переписать формулировку»
- `WEAK` → «Слабый — переписать заново»
- `CUT` → «Удалить блок»
- `MOVE` → «Перенести в другое место»
- `NOT_TOV` → «Не похоже на Михаила»
- `ADD_PROOF` → «Добавить пример / факт / кейс»
- `ADD_ACTION` → «Добавить действие для зрителя»
- `TOO_LONG` → «Слишком длинно»
- `TOO_ABSTRACT` → «Слишком абстрактно»

**Процесс:**

1. Создаю HTML-интерфейс из `templates/review-html-template.html`, заменяя плейсхолдеры:
   `PROJECT_TITLE_PLACEHOLDER`, `PROJECT_SUBTITLE_PLACEHOLDER`, `PROJECT_ID_PLACEHOLDER` (kebab-id
   проекта — ключ localStorage), `MODE_PLACEHOLDER` → `review`, `BLOCKS_DATA_PLACEHOLDER` → JS-массив
   единиц:
   ```javascript
   {n:1, t:"Хук + анонс", time:"0:00–2:30", key:"Ключевая фраза блока",
    text:`Полный текст ведущего. Абзацы разделять пустой строкой.
   Бэктики и доллары в тексте экранировать.`,
    viz:"идея визуала (1 строка)", checklist:["пункт чек-листа"]}
   ```
   Сохраняю в `sessions/[project]/review.html`. Интерфейс уже даёт: онбординг «Как пользоваться
   — 4 шага» + легенду статусов, выпадающий список статусов + поле комментария на каждый блок,
   прогресс-бар + автосохранение в localStorage, кнопку «📋 Скопировать ответы» (JSON в буфер) +
   «⬇ Скачать JSON».
2. АВТОМАТИЧЕСКИ открываю в браузере: `open sessions/[project]/review.html`.
3. Объясняю одной фразой: прочитать блоки → статус + комментарий → «Скопировать ответы» →
   вставить JSON в чат.
4. Принимаю результат как JSON (`type:"scenario_review"`, массив `blocks` с полями `block, title,
   status, status_ru, comment`). Если пользователь прислал статусы текстом — тоже принимаю, не
   настаиваю на JSON.

## Этап 8: Переписывание проблемных блоков

**Вход:** JSON из Этапа 7 (или текстовые статусы). Беру каждый блок, где `status` != `OK`.

**Правки СНАЧАЛА заносятся в `client-edits.md`, ПОТОМ применяются.** Каждый комментарий из
ревью — новая запись в реестре (раздел §Б, ID вида `Б7.1`) с дословной цитатой клиента и
классификацией по правилам «Интерпретация правок» (`05-writing.md`): **формулировка** (правишь
текст) vs **идея-задача** (артефакт/вопрос клиенту, вписывается в действии, не мета-описанием).
Только после того как правка зафиксирована в реестре — она уходит в спеку блока для
`block-writer` (`05-writing.md`) на переписывание. Это тот же fan-out, что и на первой
генерации: 1 агент = 1 блок, спека только своя, правки — по ID.

**Правила обработки статусов:**

- **`EDIT`** — сохраняю смысл, переписываю формулировку: убираю ИИ-штампы, делаю прямее,
  добавляю конкретики.
- **`WEAK`** — предлагаю 2-3 новых захода для блока.
- **`CUT`** — удаляю блок, проверяю логику сценария.
- **`MOVE`** — предлагаю, куда лучше перенести.
- **`NOT_TOV`** — переписываю ближе к голосу Михаила (по `tov.md`).
- **`ADD_PROOF`** — прошу кейс/факт или предлагаю, какой тип доказательства нужен (сверка с
  `facts.md`/`case-through/`).
- **`ADD_ACTION`** — добавляю практический шаг для зрителя.
- **`TOO_LONG`** — сокращаю до сути.
- **`TOO_ABSTRACT`** — добавляю конкретики: цифры, примеры, кейсы.

После переписывания блока новую версию staging (`.blocks-vNN/{n:02d}.md`, следующая версия
`vNN+1`) снова прогоняю через Уровень 1 preflight, и `review.html` пересобираю скриптом:
```bash
python3 reference/scripts/rebuild_review.py vNN <blocks.json>
```
**КРИТИЧНО:** версия обязана попасть и в подпись, и в ключ `SCENARIO_VERSION` localStorage —
иначе браузер вернёт клиенту ответы прошлой версии, и уже внесённые правки приедут как новые.

## Этап 9: Финальная сборка

**Процесс:**
1. Собираю все блоки после правок.
2. Проверяю логику переходов.
3. Сохраняю в `sessions/[project]/scenario-final.md`.

**Выход:**
1. Финальный сценарий — все блоки в правильном порядке.
2. Список ключевых фраз — что должно запомниться.
3. Список блоков и их функций — карта сценария.

**После сборки СРАЗУ перехожу к Этапу 9.5** (Вычитка) — не спрашиваю разрешения.

## Этап 9.5: Вычитка финала (обязательно перед выдачей)

Прохожу собранный `scenario-final.md` отдельным проходом:

1. **Орфография и грамматика** — опечатки, согласования, пунктуация. Обязательный проход, не
   пропускать.
2. **Корректная терминология** — общепринятые термины, не самодельные (например «твёрдые/гибкие
   расходы» → «постоянные/переменные расходы»). Сверяю доменные термины.
3. **Связность метафор** — каждая метафора (стакан/камень/пружина/страус) консистентна во всех
   блоках; если метафору убрали в одном месте — убрать ссылки на неё везде.
4. **Юмор и живость — `make-humor`** (доза из TOV). Прогоняю через юмор-проход: оживляю
   сухие/«методичные» блоки лёгкой иронией, бытовыми метафорами, разговорными вставками и
   инсценировкой внутреннего диалога (мини-сценки от лица сопротивляющегося мозга) — в стиле
   Михаила. Дозу беру из оси юмора TOV (`tov.md`, `knowledge-base/TOV-analysis.md`). Юмор
   «по-Михаилу»: самоирония, бытовые сценки, анекдот/культурный референс, дозированный жёсткий
   сленг («геморр», «пушка-бомба-огонь») — а НЕ каламбуры ради каламбуров. Регистр капается по
   `tov.md` (не съезжать в панибратство/гопника). НЕ ломаю смысл, факты, цифры и структуру;
   фактуру не трогаю.
   **ОБЯЗАТЕЛЬНЫЙ повторный прогон стоп-слов ПОСЛЕ юмора** — юмор-проход умеет возвращать
   вырезанные клише и усилители-вату (Г3 в `preflight.py`). Гонять `preflight.py` (или хотя бы
   его гейт Г3) заново на пост-юморной версии, до antislop:
   ```bash
   python3 reference/scripts/preflight.py --project <slug> --staging .blocks-vNN
   ```
5. **Гейт AI-слопа — `antislop`** (обязательно, после юмора). Прогоняю через детектор
   нейрослопа: сбиваю машинную структуру (триады, контрасты «не X, а Y», лесенки, «Раньше→
   Сейчас», вопросы-крючки), чищу эмодзи-декор/остаточный markdown, слежу, чтобы в каждом
   блоке была живая фактура (цифра/имя/перволичная оговорка) — она перевешивает. Фактуру не
   трогаю. Порог: не хуже `ai-assisted-light`.

Правки вношу прямо в `scenario-final.md`. Порядок жёсткий: вычитка → юмор → повторный стоп-скан
→ antislop — каждый следующий шаг может испортить работу предыдущего, поэтому финальный гейт
(antislop) идёт строго последним. После вычитки — визуальный слой (`07-visual.md`, Этап 10).
